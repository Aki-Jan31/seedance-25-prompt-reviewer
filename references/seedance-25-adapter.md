# Seedance 2.5 version adapter

Load this module only when version-specific behavior changes the revision or when the user asks for platform facts.

## Version boundary

Transferable Seedance 2.0 craft includes directing motivation, shot contracts, explicit reference responsibilities, visible action causality, continuity ledgers, anti-slop editing, dialogue ownership, and smallest-change retakes. Do not transfer 2.0 hard parameters to 2.5: duration ceilings, asset counts, model IDs, API fields, extension mechanics, real-person-material rules, resolutions, pricing, or surface capabilities.

When the line or surface is unknown, keep editing the prompt with generic craft rules but withhold platform numbers and guarantees. Do not rewrite a user's stated 2.5 prompt into a 2.0 workflow.

## Duration routing

- For an existing 2.5 prompt intended as one direct generation, preserve 19-second, 22-second, and 30-second timelines as a single prompt. Never split them merely because Seedance 2.0 used a 15-second ceiling.
- Treat `up to 30 seconds in one generation` as the 2.5 repository's current version-adaptation claim, not as proof that every provider, account, region, or operation exposes the same option.
- The upstream claims of platform extension to 90 seconds and a 180-second long-video mode are marked third-party observed or unverified locally. Preserve that evidence level, name the surface, and verify current availability before operational advice.
- Adjust an existing timestamp boundary only when the user permits timing edits. Otherwise repair content inside the locked intervals.

## Multi-range prompt checks

For every time range, carry forward:

- exact character identity and label;
- wardrobe and current damage/wetness/prop state;
- prop ownership and hand;
- left/right, foreground/background, facing, eyeline, and screen direction;
- motivated source and phase of light;
- action start and end state;
- sound/dialogue state;
- camera endpoint that the next range inherits.

Time ranges must cover the declared total duration without unintended gaps or overlaps. Do not add a fifth or sixth segment just because a template used that count; segment where the user's action changes.

## Material and feature claims

The ye4wzp adaptation reports higher 2.5 reference ceilings, timestamp/region editing, segment retake, green-screen or white-model references, authenticated-face behavior, extensions, and long-video options with mixed evidence. These are not universal guarantees. Before changing tags, counts, upload plans, or edit instructions:

1. identify the exact surface and operation;
2. use current official documentation where available;
3. label third-party tests and repository hypotheses as such;
4. leave unknown API fields and model IDs unknown rather than borrowing 2.0 names.

Do not modify the user's existing material numbering to match any remembered ceiling. More supported inputs make clear role assignment more important, not optional.

## Evidence labels

- `官方/当前已核验`: supported by current official documentation for the named surface and operation.
- `上游汇总`: stated by an upstream repository, with its date and source type preserved.
- `第三方实测`: observed by a named third party; not an official or universal promise.
- `待验证`: hypothesis or untested claim. Use only as a test proposal.

Always end a text-only review with the distinction between prompt consistency and untested render quality.
